# Authentication audit — 25 October 2026

## Decision and evaluator access

**A brand-new visitor cannot currently register a private account.** Email verification is required, but the tested delivery service is not configured. Both UI and server reject new signup; the server creates no stranded inactive account. Existing verified private accounts can log in. Required verification has not been bypassed.

The supported assessment path is `/users/sign_in` → **Try the public demo**. It requires no Sounding email or password, creates a real server session with a visitor-isolated workspace, and supports the product journey. Signing out discards that demo workspace; the next entry gets a clean workspace. Never use the public demo for confidential material. This is demo access, not private-account registration or password recovery. The preview still has Vercel Authentication, so evaluators need access to that protected deployment separately.

No high-severity authentication defect was confirmed in this audit. No runtime authentication code, email policy, secrets, provider integrations or session architecture was changed. Changes are focused security regression tests, a read-only secret audit and this verified report. The absence of email delivery remains a submission limitation, not a completed email feature.

## Scope and regression evidence

- 58 application tests pass, including five new authentication regressions: no-mail signup creates no inactive account; duplicate signup cannot replace credentials; wrong-password/unknown-email equivalence; session fixation protection; invalid signup credential rejection. Existing password-hash checks now verify random salts and correct/incorrect passwords.
- Expanded real HTTP checks cover missing Origin, disabled verification resend, disabled raw reset, forged session cookies, owner spoofing, stale revisions, demo isolation and logout. Existing private-recording security checks preserve actual uploaded media and processing gates.
- The preview browser tests used the existing ignored QA credentials without printing them. No new private Neon user, provider configuration or verification/reset token was created or exposed. In-memory fixture accounts and mail sinks are not real email delivery.
- TypeScript, lint and production build pass. Configured-secret/UTF-8 checks and production-dependency audit pass with zero reported vulnerabilities.
- No paid API calls, real email messages or OAuth requests were made.

Before enabling private signup in a future task: configure and actually verify delivery, retain required verification, complete password-confirmation/name-edge-case validation, and run an actual fresh-signup → delivered verification → login → isolated-workspace browser test. This audit does not authorize enabling those features.
