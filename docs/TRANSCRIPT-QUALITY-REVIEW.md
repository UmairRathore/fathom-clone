# Module 1 transcript quality diagnosis

## Root cause and evidence

The apparent final-25-second transcript is a **rendering/windowing problem**, not a shortened media submission or a truncated Neon meeting. The old UI rendered one large card per short provider segment and virtualized every recording. At the end it mounted only the final eight segments; selecting that visible page text also captured tool labels. Its Copy Transcript implementation already used all saved segments rather than the DOM, but this distinction was not clear in the UI.

The supplied Fathom reference has approximately 555 normalized words including headings; Sounding has 526 normalized words (520 whitespace-separated tokens). All three explicit assignee names in the reference occur in the saved Sounding transcript. These counts do **not** measure word error rate or prove equivalent transcription accuracy; Fathom is another model output, not independently verified ground truth.

**Audit limitation:** the original provider response envelope was not retained separately. The durable value is its normalized transcript. Exact raw top-level text/segment equality cannot be proved retrospectively. The code retains every nonempty segment, and the stored transcript spans the recording; this rules out the reported four-minute disappearance downstream, but does not establish that every spoken word was recognized. No missing wording was reconstructed from the Fathom text. A model retest is not justified by the windowing issue and has not been performed or authorized.

## Fix without paid calls

- Adjacent same-label speech is grouped at sentence/pause/length boundaries, with a maximum 35-second/95-word paragraph and a 2.5-second gap threshold. Highlight boundaries also split groups. Source segments, words, IDs and fractional timestamps stay unchanged.
- Each phrase remains independently clickable at its original timestamp; active phrase/paragraph tracking respects silent gaps. A single set of annotation controls acts on the selected source segment in each paragraph.
- Short recordings (up to five minutes/250 segments) render their entire filtered transcript. Longer meetings keep virtualization, with an explicit explanation and beginning/end controls that move the reading window without changing playback.
- A full-transcript status shows total source segments, paragraph count, first/last speech time and media duration. Anonymous voice attribution is explained explicitly.
- Copy full transcript and Download transcript share one pure formatter operating on the complete meeting array, independent of scrolling/search/speaker filters. It emits paragraph timestamps and labels, with the original speech exactly once and no UI tool text. Clipboard rejection still presents the existing download fallback.
- Highlight association uses actual time-range intersection; no existing stored highlight or manual annotation is rewritten. Whitespace-only provider speaker labels now correctly remain unknown for future normalization.
